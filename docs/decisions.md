# Decision Log

| Phase | Decision | Reason | Alternatives considered |
|---|---|---|---|
| Phase 0 | Confirm MovieLens 100K (`ml-100k`) as dataset | Standard academic benchmark for collaborative filtering, rich interaction density (93.7% sparsity), ideal scale for viva demonstration and testing. | MovieLens 1M (unnecessary computational overhead for real-time viva demo); synthetic datasets (unrealistic user distribution). |
| Phase 0 | Confirm core stack (Python, NumPy, pandas, SciPy, scikit-learn, pytest, Streamlit) | Standard data science stack enabling transparent, scratch-built mathematical implementations without black-box abstractions. | Surprise, LightFM, FastAI (abstracts mathematics, hindering viva explanations). |
| Phase 0 | Confirm 4 models: Popularity Baseline, User-KNN, Item-KNN, Truncated SVD | Covers canonical CF taxonomy: non-personalized baseline, user memory-based, item memory-based, and latent factor matrix factorization. | Deep learning / neural CF (adds unnecessary complexity without demonstrable benefit on 100K ratings). |
| Phase 0 | Confirm per-user chronological 60/20/20 split | Prevents temporal data leakage and simulates real-world production forecasting while guaranteeing user representation in training. | Random interaction split (severe future-to-past leakage); global timestamp cutoff (leaves early users with no test data and late users with no train data). |
| Phase 0 | Confirm relevance threshold $r \ge 4.0$ for Top-$N$ ranking | In 5-star rating systems, ratings of 4 and 5 represent genuine positive interest/satisfaction. | Any rated movie as relevant (rewards recommending disliked movies); threshold $\ge 3.0$ (too noisy). |
| Phase 0 | Confirm candidate set as all unseen catalog movies | Models must rank across the full unconsumed catalog ($I \setminus \text{Seen}_u$) to reflect realistic recommendation scenarios. | Ranking only test items (inflates hit metrics artificially and distorts catalog ranking). |
| Phase 0 | Confirm primary model selection metric: Validation NDCG@10 (RMSE secondary) | Top-$N$ recommendation utility in user interfaces depends on top-rank relevance quality rather than minor rating estimation errors on unread items. | RMSE alone (penalizes accurate top-rank ordering if absolute scores shift); Precision@10 alone (ignores position discounts). |
| Phase 0 | Mean-center observed entries in sparse matrix for Truncated SVD | Mean-centering the full matrix across missing entries turns a 93.7% sparse matrix into a dense matrix of 1.58M floats; centering observed entries preserves SciPy CSR sparsity. | Full dense matrix materialization (violates memory constraints and non-negotiable rule 6). |
| Phase 1 | Use `requests` with `certifi` in download script | Standard Windows `urllib` calls fail on default certificate chains for GroupLens; `requests` bundled with `certifi` resolves SSL certificates cleanly and supports streaming. | Custom OpenSSL certificate injection; downloading zip manually. |
| Phase 1 | Pass user-only WiX Burn flags to Winget Python installer | Standard Python installer defaults to installing `py.exe` machine-wide (`InstallLauncherAllUsers=1`), triggering elevation failure code 50; overriding with `InstallLauncherAllUsers=0 Include_launcher=0` allows clean user-scope execution. | Machine-wide administrator installation. |
| Phase 2 | Gating kNN neighborhoods to positive similarities ($s > 0$) | Negative Pearson/cosine similarities in standard collaborative filtering often introduce noise or inverted preference weights unless modeled symmetrically. | Including negative weights (distorts neighborhood mean adjustments); absolute value weighting. |
| Phase 2 | Hierarchical Fallback Chain ($\mu_i \to \mu_u \to \mu$) bounded in $[1, 5]$ | When co-ratings are sparse or denominators vanish, falling back down the item-then-user-then-global hierarchy guarantees continuous, bounded, well-defined predictions. | Defaulting to 0 (violates non-negotiable rule 1); defaulting to 3.0 constant (ignores entity priors). |
| Phase 2 | Secondary tie-breaker by `item_id` in `recommend()` | Guarantees 100% deterministic ranking when candidate items have identical predicted scores. | Random tie-breaking (causes flaky ranking evaluations); unstable sort order. |
| Phase 3 | Pre-commit to Validation NDCG@10 as Primary Selection Metric | Top-$N$ ranking utility in recommendation interfaces is driven by placing relevant items at top ranks, which NDCG@10 captures via logarithmic discounts, whereas RMSE penalizes uniform scale shifts that do not harm ranking order. | RMSE alone (selects UserKNN which produces near-zero ranking utility); Precision@10 alone (ignores position discounts). |
| Phase 3 | Select Truncated SVD ($n_{\text{factors}}=20$) as Winning Architecture | SVD achieved the highest validation NDCG@10 (0.1138) by learning dense latent factor representations that generalize across sparse unrated candidates, outperforming popularity (0.0702) and kNN (0.0050). | Popularity baseline (lacks personalization, low catalog coverage); higher factor dimensions $n=30, 50$ (overfitted validation split). |
| Phase 3 | Inverted Index Candidate Co-Rater Pruning for ItemKNN `recommend()` | Any candidate item sharing 0 co-raters with a user's rated items has mathematically guaranteed 0.0 adjusted cosine similarity and directly receives fallback predictions; pruning these reduces similarity checks while preserving 100% exact numerical rankings ($< 10^{-9}$ tol). | Evaluating all $1,600+$ candidate items per user brute-force (high latency); approximate nearest neighbors (sacrifices exact reproducibility). |
| Phase 3 | Cold-Start Truncation Protocol ($M \in \{1, 3, 5, 10\}$) | Simulates real-world onboarding curves by truncating training histories while evaluating on the same validation targets, proving Popularity is best at $M=1$ and SVD takes over at $M \ge 3$. | Synthetic user profiles (unrealistic interaction distributions); evaluating cold-start on held-out test data (violates single-test evaluation rule). |
| Phase 3 | Exclusion of Zero-Relevant Users from Ranking Metrics | Users without any test rating $r \ge 4.0$ have undefined IDCG@K ($0.0$), which would cause division-by-zero or distort macro-averages; counting and excluding them (25/943 test users) maintains mathematical integrity. | Treating NDCG as 0.0 (penalizes models for user preference sparsity); treating NDCG as 1.0 (inflates scores). |
| Phase 4 | Online SVD Folding-In via Right Singular Vectors | Fold ad-hoc visitor ratings $x$ into latent SVD space via $\hat{r} = \mu + (x V) V^T$ in $< 2$ ms, yielding exact numerical equivalence ($< 10^{-14}$) to retraining without expensive matrix decomposition. | Refitting SVD on every user rating (unacceptable multi-second UI latency); falling back strictly to memory-based heuristics for new profiles. |
| Phase 4 | Cold-Start Personalization Threshold at $N_{\text{min}} = 3$ Ratings | Empirical findings from Phase 3 cold-start sensitivity curves demonstrated SVD overtakes Popularity at $M \ge 3$, while Popularity provides the superior safety net at $M < 3$. | Arbitrary threshold (e.g. 10 ratings); forcing SVD on 1 rating (poor semantic alignment). |
| Phase 4 | Pure HTML Table Rendering in Streamlit UI | Bypasses pyarrow binary ABI incompatibility on Windows with NumPy 1.26 while producing clean, styled, responsive tables with zero external dependencies. | Forcing pip reinstall of pyarrow; raw unformatted text dumps. |
| Phase 4 | Grounded Item-Similarity Explanations via SVD Latent Cosine Space | Identifies the user's highest-similarity positively rated movie ($s > 0.10$) using SVD item factor cosine similarity, ensuring 100% mathematical fidelity to model signals with zero fabricated text. | Generative LLM explanations (prone to hallucinating plot points); static ungrounded boilerplate. |
| Phase 5 | Integration Suite Expansion (End-to-End Pipeline & Leakage Invariance) | Added `tests/integration/test_end_to_end.py` and `tests/integration/test_leakage.py` guaranteeing pipeline-wide temporal invariants and proving zero model drift when test data is modified. | Relying solely on isolated unit tests; manual testing. |
| Phase 5 | Traced System Resource & Latency Measurements | Measured actual wall-clock execution time and peak memory using `tracemalloc` and `perf_counter` (establishing 2.86 ms folding-in latency and 12.75 MB peak SVD training memory) to satisfy empirical rigor requirements. | Heuristic asymptotic estimates; unverified performance claims. |
| Phase 5 | Comprehensive 16-Question Viva Defense Examination Framework | Formulated `docs/viva_prep.md` addressing critical examiner challenges (RMSE vs. NDCG divergence, sparsity normalization, cold-start handling, MNAR bias, scaling to 20M) with rigorous mathematical proofs and intuitive analogies. | Generic bullet-point summaries; relying on memory during viva defense. |
